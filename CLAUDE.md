# CLAUDE.md

Guidance for Claude Code in this repository. Keep this file small: it is
loaded in every session. Detail lives in `docs/agents/` and `docs/`.

## Rules for this file

- Add here only what is needed in nearly every session and cannot be found
  by reading the code, `git log` or the docs: hard rules, safety, decisions
  settled by the user, pointers.
- No dated history, results, measurements, per-feature switches, experiment
  notes or "how X works". Those go in `docs/JOURNAL.md` (history) or the
  matching `docs/agents/` file (current state).
- A new fact about a subject goes in that subject's `docs/agents/` file, not
  here. If it needs a new file, create one and add one line to the table
  below.
- Before adding a line, ask whether a future session would be worse off
  without it. If not, leave it out. When touching this file, delete what is
  stale or has moved.
- Keep each `docs/agents/` file about one subject, and say at its top when
  to read it.

## Goal

An open-source (MIT) graphics driver for Mac OS X 10.4 Tiger on PowerPC for
the AMD Radeon HD 7570 ("Turks", Northern Islands, DCE5; `1002:675d`). Target
machine: Power Mac G5 Late 2005. Development runs Tiger under
`qemu-system-ppc -M mac99` with the card passed through (VFIO).
`PROMPT.md` is the user's original brief.

## State in brief

- **Phase 1 (framebuffer) is complete** and confirmed by the user: QEMU and
  the real G5, DVI-I and DisplayPort, modes from the EDID, hot-plug on DVI-I,
  Open Firmware display support installed on the G5.
- **Phase 2 (acceleration) works**: Mesa 26.2.4 `r600` on the card behind a
  `gld*` GL bundle and a kernel half in `hw/`; Quartz Extreme, Core Image
  and full-screen/windowed GL games run on the G5.
- Phase 3 (video decode, `docs/UVD.md`): UVD runs on the G5, the `rdnvd` library decodes H.264 bit-exactly and
  a QuickTime component (`quicktime/`, installed on the G5) uses it in QuickTime Player; 1080p60 is too slow
  (serial pipeline, `docs/UVD.md`); PowerVLC is not built.
- The real G5 holds the card and runs the installed kext. The user plays
  games on it: never `killall` a program there, and a window server restart
  needs the user's yes.
- Reach the G5 and the guest with the `test-macs` skill (`scripts/mac.sh`),
  never by hand-built ssh lines.
- Only the user can see the card's output. See "Verification".

## Hard rules learned the hard way

- `bool` has four bytes on Tiger PowerPC. Mesa code assuming one breaks
  silently there and not in the Linux big-endian test build. Suspect it
  first when something works on Linux and not on Tiger.
- Mesa is changed only through `mesa/patches/`. The Tiger build of Mesa
  needs `-fno-strict-aliasing`.
- After changing the device layer, check the Tiger bundle with `nm -u` for
  our own symbols: a missing one shows only when the window server fails
  to load it.
- Never write properties to `IODisplayWrangler` (Tiger panics).
- After a presentation change, grab the screen before measuring
  (`scripts/mac.sh g5 grab`); a frame rate proves nothing. A grab of a
  moving scene is a collage.
- Open Firmware's nvramrc is one line: never `\` comments, never long lines
  in `boot-command`. The G5's wired keyboard must be plugged in before
  power-up. After a hang expect two power cycles.
- `radeon` is blacklisted on the host because unbinding it oopsed the
  kernel.

## Host safety rules

The host is the user's server, reached over ssh. Stop and ask before:

- Rebooting it or changing how it boots (kernel parameters, initramfs,
  blacklists).
- Touching the host GPU, `0000:30:00.0` (Cezanne iGPU, `amdgpu`), or anything
  that could cost the user access. The chipset's IOMMU group 9 includes the
  NIC; never bind any of it to `vfio-pci`.
- Enabling `mmiotrace` (it takes all CPUs but one offline).
- Starting a `mac99` passthrough guest in a host boot where `radeon` has
  been bound to the 7570: that combination oopsed the host kernel once.
- Driving the card's command processor (`rdn_tool accel`, `rdn_gltest`, a
  guest with the accelerator) without `scripts/card-quiet.sh apply` first.
  On 2026-10-05 the host reset with a data fabric sync flood during such
  tests; the user approved masking the card's PCIe error escalation at
  runtime. A host reboot undoes the masking, and a reset of the card undoes
  the card's half: apply again. `sync` before a test that has never run.
- Writing to the card's flash. Nothing is ever flashed.
- Abandoning a design decision below.

Bind the 7570 at runtime with sysfs `driver_override`. The only persistent
host configuration is the user-approved `blacklist radeon` file. Tell the
user as soon as something needs them physically.

## Design decisions (settled by the user)

- One hardware library (`hw/`) shared by the Linux tool and the kext. It
  must not depend on Linux or IOKit; everything goes through the OS layer
  (`hw/rdn_os.h`). Freestanding C99 that also compiles with Apple gcc 4.0.1.
- Endian-clean from the first line (the target is big-endian): explicit
  accessors for registers and VBIOS tables, no bitfields over AtomBIOS
  structures. Big-endian correctness is tested under `qemu-ppc`.
- Microcode (`TURKS_pfp`, `TURKS_me`, `BTC_rlc`, `TURKS_mc`) and the VBIOS
  are git-ignored (`firmware/`, `private/`), injected at load time, never
  committed. Microcode may ship in the G5 package, unmodified with its
  licence.
- The VBIOS comes from the PCI expansion ROM with a load-from-file fallback,
  never from the x86 legacy address. Under QEMU the file is the only source.
- Cold POST follows the Linux `radeon` initialisation order.
- Apple's GL plug-in ABI is learned by observation and by reading
  disassembly to understand the interface; all code is written fresh.
  Findings go in `docs/GLD-INTERFACE.md`.
- Mesa is the newest release (26.2.4), not an older one that builds more
  easily.
- Mesa and the GL bundle may be cross-compiled on the host
  (`scripts/darwin.sh`). The kext is always built inside the Tiger guest
  with Xcode 2.5 and Apple's gcc.
- Under QEMU the kext is always loaded freshly built from a temporary
  directory (`scripts/kext.sh up`), never from an installed copy. On the
  real Mac it is installed by the package (`scripts/make-g5-package.sh`).
  A package rehearsed in the guest must be uninstalled again afterwards.
- QEMU: emulated VGA stays primary; `vfio-pci` with `x-no-mmap=on` for
  register traces; no `x-vga`. QEMU must be the patched build
  (`scripts/build-qemu.sh`).
- Mac OS X 10.4, for Classic. If it becomes a serious obstacle versus 10.5,
  explain why before switching.
- Features that change what programs see (extension list, renderer name,
  glthread, GART, clocks) are on or off by the user's decision; do not flip
  a default without asking.

## Verification

Only the user can see the 7570's output. Exhaust self-checks first: register
readback, comparison with the reference trace, EDID validity, `ioreg`, guest
kernel log, screen grabs. When eyes are needed, ask one concrete question,
use test patterns that are unambiguous to describe, and batch the checks. Do
not mark a milestone done before the user confirms. Before a long run or an
install on the G5, tell the user what runs and for how long.
